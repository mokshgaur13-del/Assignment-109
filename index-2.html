Question 1: List four primary characteristics of a modern digital computer and identify the key hardware technology associated with each of the five generations of computers.

Four characteristics of a modern digital computer

  1. Speed: A computer performs millions or billions of operations per second.
  2. Accuracy: It produces accurate results when the data and instructions supplied are correct.
  3. Storage: It can store large amounts of data and retrieve it quickly when required.
  4. Automation and diligence: Once programmed, it can work automatically and repeat tasks consistently without tiring.

Question 2: Explain the flow of data, instructions and control signals within the functional block diagram of a computer, detailing the interaction between the CPU, memory unit and I/O interface.

A computer system mainly consists of the input unit, memory unit, central processing unit (CPU), output unit and the buses that connect them.

  • Input unit: Accepts data and instructions through devices such as a keyboard or scanner and converts them into a form the computer can process.
  • Memory unit: Stores program instructions, input data, intermediate results and final results. RAM holds information currently in use, while secondary storage keeps data for longer periods.
  • CPU: The Control Unit (CU) fetches and decodes instructions and directs their execution. The Arithmetic Logic Unit (ALU) performs arithmetic and logical operations. Registers hold small amounts of data and instructions for immediate use.
  • I/O interface: Connects peripheral devices to the system and manages differences in speed, data format and communication methods.
  • Output unit: Presents processed information through devices such as a monitor, printer or speakers.

Working sequence: An input device sends data through an I/O interface to memory. The CPU fetches an instruction and required data from memory, decodes the instruction, and processes it. The Control Unit sends control signals to coordinate memory reads/writes and I/O operations. Results are stored in registers or memory and then sent through the output interface when needed.

System buses: The data bus carries data, the address bus identifies a memory location or I/O device, and the control bus carries signals such as read, write and interrupt.
Question 3: Demonstrate how optical data-scanning devices (e.g., barcode/OMR scanners) and electronic card readers (e.g., RFID/smart card readers) can be deployed in a campus environment to automate student attendance and library checkouts.

1. Attendance automation

  1. Each student receives an ID card with a printed barcode or an RFID tag.
  2. At the classroom entrance, the student scans the barcode or taps the card on a reader.
  3. The reader captures the ID and sends it to the campus attendance application.
  4. The application checks the student record, course, class schedule and time, then records attendance in a database.
  5. Teachers can review attendance reports and identify students who may need follow-up.

2. Library checkout automation

  1. Books are labelled with barcodes or RFID tags, and each student has a library ID card.
  2. At the circulation desk or self-service kiosk, the student card and book are scanned or read.
  3. The library system verifies the account, checks the book's availability and records the loan and due date.
  4. When a book is returned, the system updates its status and calculates any overdue charge according to library rules.

Benefits and safeguards: These systems reduce manual entry, save time and improve reporting. Access should be limited to authorised staff, data should be protected, and the campus should provide a manual correction process for missed or incorrect scans.

Question 7: Critique the operational reliability and security vulnerabilities of vision-input devices (facial recognition) compared to voice-recognition devices when deployed as primary biometric authentication tools in high-ambient-noise, publicly exposed environments.

Facial recognition and voice recognition can make authentication convenient, but neither is perfectly reliable or secure. In a noisy, public environment, the choice should account for environmental conditions, spoofing risks, privacy and the consequences of a false match.

FactorFacial recognitionVoice recognition
Environmental reliabilityCan be affected by poor lighting, camera angle, masks, occlusion and changes in appearance.Ambient noise, reverberation, distance, illness and microphone quality can reduce accuracy; high noise is a major disadvantage.
Spoofing risksPhotos, videos or masks may attack weak systems; depth checks and liveness detection can reduce risk.Recordings, replay attacks or synthetic/deepfake voices may attack weak systems; challenge-response and anti-spoofing checks help.
Public privacyMay capture bystanders and can enable unwanted tracking if poorly governed.May record bystanders or conversations; voice samples can reveal personal information.
UsabilityCan be hands-free and quiet, but needs a suitable camera view.Hands-free and useful for accessibility, but speaking a passphrase publicly can be inconvenient and unsafe.
Recommended controlsLiveness detection, secure templates, rate limiting, access logs and a fallback method.Noise-resistant microphones, anti-replay checks, secure templates, rate limiting and a fallback method.

Assessment: In a high-ambient-noise location, voice recognition is generally less operationally reliable because noise can interfere with capturing and matching speech. Facial recognition may perform better if lighting and camera placement are controlled, but it remains vulnerable to spoofing, bias and privacy concerns. Neither should be the sole protection for high-risk access.

Recommendation: Use biometric liveness checks alongside a second factor, such as a secure card or PIN, for sensitive areas. Encrypt biometric templates, limit retention and access, obtain appropriate consent, test performance across user groups, and provide a non-biometric alternative.

Question 8: Design an accessible, hands-free computer workstation tailored for a visually impaired user. Propose a coherent integration of non-visual input devices (such as voice recognition systems and tactile keyboards) with specialised output devices (such as voice response synthesizers and screen readers).

An accessible workstation should let a visually impaired user operate a computer independently using speech, tactile controls and audio feedback. The design should be adjustable to the user's preferences and tasks.

Proposed system components

  • Computer and operating system: Use an operating system with built-in accessibility features and strong support for assistive technology.
  • Screen reader: Install a screen reader such as NVDA, JAWS or VoiceOver. It reads menus, text, controls, notifications and document content aloud.
  • Speech output: Use clear text-to-speech with adjustable voice, speed and volume. A good headset or speakers provide private or shared audio as appropriate.
  • Voice recognition: A microphone and speech-recognition software allow dictation, launching applications, navigating menus and issuing commands. A headset microphone can improve recognition accuracy.
  • Tactile keyboard: Provide a keyboard with raised home-row markers or high-contrast, large-print key labels. Keyboard shortcuts should be available for frequent actions.
  • Refreshable braille display (optional): Converts on-screen text into tactile Braille cells and is valuable for users who read Braille or need quiet access.
  • Accessible applications: Prefer software with labelled controls, keyboard navigation, meaningful headings and compatibility with screen readers.
  • Backup and support: Include a way to recover from voice-recognition errors, accessible help instructions, automatic saving and regular software updates.

How the workstation operates

  1. The user speaks a command or dictates text through the microphone, or enters commands using the tactile keyboard.
  2. Speech-recognition software converts speech to commands or text; the operating system sends the action to the relevant application.
  3. The screen reader detects changes in the interface and announces labels, focus, text and error messages through speech synthesis.
  4. The user listens to the feedback and corrects or confirms the action using speech or keyboard shortcuts. A Braille display can provide tactile output where available.

Accessibility and safety considerations

Provide adjustable speech rate and volume, support for the user's preferred language, quiet audio options, clear confirmation before destructive actions, and a manual alternative when speech recognition fails. Keep private information out of loudspeaker output in shared spaces, protect voice recordings and personal data, and test the complete workstation with the intended user.

Conclusion: Combining voice input, tactile keyboard access, a screen reader and optional Braille output creates a flexible workstation that supports hands-free operation without making speech the only way to interact.
